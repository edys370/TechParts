1. Justificación de la Temática TechParts

El comercio electrónico de partes y componentes de computadoras requiere una rigurosa arquitectura de persistencia por dos factores esenciales:

  • Variantes Técnicas con Control de Stock Independiente: Una tarjeta gráfica o módulo de memoria RAM no es un producto genérico. Cada variante (ej. capacidad de 1TB vs 2TB, o modelo estándar vs Overclocked Edition en blanco) posee su propio SKU, costo y stock independiente. TechParts diseñó la entidad ProductVariant vinculada a un producto padre consolidado.
  • Riesgo Crítico de Incompatibilidad: Para prevenir compras erróneas (sockets AM5 vs LGA1700, memorias DDR4 vs DDR5), TechParts integró un motor de reglas de compatibilidad en backend y canal de asistencia técnica directa vía WhatsApp en cada ficha.

2. Arquitectura de Base de Datos y Persistencia Relacional

El esquema relacional implementado en PostgreSQL garantiza integridad referencial estricta y trazabilidad absoluta a través del patrón Libro Mayor de Inventario (Inventory Ledger):

Entidad Rol en el Sistema Relaciones y Restricciones
Category Agrupación de hardware (CPUs, GPUs, RAM, SSD, Fuentes). 1:N con Product. Slug único indexado.
Product Producto base o consolidado de hardware. N:1 con Category, 1:N con ProductVariant.
ProductVariant Variaciones técnicas (capacidad, color, edición). 1:N con Product (Cascada). Stock independiente.
InventoryTransaction Historial inmutable de auditoría de cada movimiento (IN/OUT/ADJ). Guarda previousStock, quantity, newStock y referencia.
User Usuarios con roles administrativos y de almacén. Email único y control de acceso.

3. Estrategia de Concurrencia y Garantías Transaccionales ACID

Para impedir el fenómeno de sobreventa (overselling) ante compras simultáneas, TechParts utiliza bloqueos pesimistas de fila en PostgreSQL mediante SELECT ... FOR UPDATE: 

// Fragmento de InventoryService (registerMovement)
return prisma.$transaction(async (tx) => {
  const [product] = await tx.$queryRaw`
    SELECT id, sku, stock FROM products WHERE id = ${productId} FOR UPDATE
  `;
  if (product.stock < quantity) {
    throw new Error(`Stock insuficiente para el SKU ${product.sku}`);
  }
  await tx.product.update({ ... });
  await tx.inventoryTransaction.create({ ... });
});
Garantía de Cero Sobreventas: Toda transacción paralela espera en cola a que la anterior libere el bloqueo. Si el stock llega a cero, las operaciones subsiguientes son rechazadas inmediatamente de forma segura (400 Bad Request), impidiendo existencias negativas.

4. Dockerización e Infraestructura

La orquestación se realiza mediante Docker Compose con aislamiento completo:

  • Imagen Oficial: postgres:16-alpine (consumo mínimo de recursos y alta seguridad).
  • Persistencia de Volúmenes: Volumen nominal techparts_pgdata que asegura la supervivencia de datos tras reinicios de servidor.
  • Healthcheck Automático: Sondeo continuo cada 5 segundos mediante pg_isready.
  • Mapeo de Puertos: Puerto configurable 5435:5432 para evitar conflictos con otras bases de datos locales.

Plantillas de Correo Transaccionales Integradas:

  1. Factura Digital al Cliente: Detalle de productos, desglose de IVA (15%) y total facturado.
  2. Alerta de Stock Bajo al Administrador: Notificación automática cuando las existencias descienden por debajo de minStock.
  3. Aviso de "Vuelve a estar disponible": Notificación a clientes ante reposición de productos agotados.

6. Respaldos (Backup) y Recuperación ante Desastres (DRP)

TechParts incorpora herramientas automatizadas de volcado y restauración:

  • Volcado en Caliente: npm run db:backup genera backup/techparts_dump.sql (23.2 KB) mediante pg_dump.
  • Restauración Inmediata: npm run db:restore restaura completamente esquemas y registros en segundos.
  • Equivalencia WooCommerce: Si se utilizase WordPress, la entrega se realiza mediante archivo empaquetado de All-in-One WP Migration (.wpress).
